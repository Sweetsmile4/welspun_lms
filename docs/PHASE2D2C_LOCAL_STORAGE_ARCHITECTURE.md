# Phase 2D.2C local storage architecture

The local integration database is a separately owned disposable target. `createLocalIntegrationDatabase` performs configuration validation but does not connect on import or construction. `connect({ explicitlyAllowConnection: true })` is the only connection path. The URI must be credential-free `mongodb://` literal loopback IP with an explicit port, use `welspun_lms_integration_*`, include `appName=welspun-lms-local-integration-v1`, and match the explicit database name. Pool size is bounded to five; selection, connect and socket timeouts are bounded. Production construction/use and duplicate URI options are rejected. Local hostname DNS resolution is not used. The frozen configuration and an adapter-private connection registry prevent a caller from supplying an arbitrary similarly named connection. Post-connect verification asserts the owned loopback connection and database name match the contract.

The adapter rejects Atlas SRV, remote hosts, userinfo, the shared `welspun_lms_dev` name, unmarked loopback targets and unsupported options. Failure text never contains a URI or driver error. Cleanup requires both an explicit cleanup intent and the ownership marker, re-validates the target, requires a connected owned database and only drops the named owned database. There is no fallback to test adapters.

Existing Mongoose domain models remain the source of truth. Stores continue to require a mapped transaction session, and the integration foundation does not register itself in normal API or worker composition. All domain, audit and command receipt work must continue to share the organization-fenced transaction. The new models are registration/setup metadata only; they do not issue identity or expose routes.

The future use of a local integration database is operator-controlled and disposable. It is not a security boundary against trusted server code, a production durability claim, or permission to connect to Atlas.

The registry binds the actual Connection object to the exact configured database name and port; setup and cleanup reject unregistered connections. The ownership/appName marker is an operator acknowledgement, not a secret or proof against malicious same-user processes. Cleanup can only drop that one connected disposable database; it cannot use the shared welspun_lms_dev name. No new authenticated domain composition is supplied.
