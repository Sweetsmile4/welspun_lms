# Phase 2D.1 UI testing guide

All workflows are synthetic and tab-memory only. No browser-to-backend integration is claimed.

## Local manual review

```powershell
$env:LMS_UI_PREVIEW='true'
npm run dev:web
```

- http://127.0.0.1:3000/development/courses - searchable draft management, builder and release history.
- http://127.0.0.1:3000/development/reviews - review, assignment, decisions and readiness.
- http://127.0.0.1:3000/development/catalog - published snapshot discovery.
- http://127.0.0.1:3000/catalog - unchanged employee placeholder.

Use in-app navigation to retain fixtures. Published detail URLs are generated by View in Development Catalog; a fresh browser tab or reload starts fresh state.

1. Search by title/code, filter archived/active and inspect counts. A published course can still have an active draft.
2. Create a course; edit metadata; add/edit/remove modules and lessons. Use arrow reorder buttons and verify displayed sibling numbers. Invalid title/description shows inline feedback on blur; malformed content/code/metadata is blocked on submission. Save advances revision; unsaved fields are discarded by switching views/course.
3. Configure the explicit synthetic approval scenario, submit, assign independent synthetic reviewers, record category/message decisions. Inspect progress, evidence and revision/digest. Changes-requested/rejected require an edited revision and new submission.
4. Edit after submission and verify stale warning/readiness refusal. Complete a fresh review; switch publisher; check all readiness reasons.
5. Publish: cancel once and verify no release, then confirm. Inspect latest label, timestamp, revision, digest and evidence. Follow View in Development Catalog. Edit the draft and verify published content unchanged; review/publish the next version and verify previous history remains.
6. Cancel archive and verify editable state; confirm archive and verify read-only state with published snapshots preserved. Reset clears shared evidence/releases.
7. Use keyboard Tab, visible focus, tablist Arrow/Home/End and native dialog Escape/cancel. Check desktop/tablet/mobile layout and no horizontal page overflow. Test no-access visibility and empty catalog filters.

## Automated validation

```powershell
npm run check
$env:START_LOCAL_MONGO_FOR_TESTS='true'
$env:MONGOD_BINARY='C:\Program Files\MongoDB\Server\8.0\bin\mongod.exe'
npm run test:mongo:local
$env:PLAYWRIGHT_PORT='4317'
npm run test:e2e
node scripts/check-preview-disabled.mjs
node scripts/check-preview-disabled.mjs --unset
node work/phase1b1-startup.mjs
node --require ./work/no-outbound.cjs backend/worker/dist/index.js
npm audit --audit-level=high
```

Build before browser/guard/startup checks. Playwright owns its loopback server and must not reuse a running development server. Mongo tests explicitly own/dispose a synthetic local replica set; they are separate from UI tests. Existing tests are retained; confirmation-aware workflows accept native dialogs, while dedicated cases verify cancellation.

New refinement coverage exercises search, lifecycle, state-derived counts, inline validation, archive cancellation/confirmation and responsive layout. Existing workflow test additionally verifies publish cancellation. Existing desktop/mobile tests retain creation/editing, module/lesson order, review assignment/decisions, readiness, immutable history, catalog, filters, keyboard tabs, employee placeholders and absent runtime preview flag.

Screenshots are generated in Playwright test output directories: course-management-refinement.png, course-workspace.png, release-snapshot.png and development-catalog.png. Use the implementation report for actual execution results and limitations; these tests do not establish production accessibility compliance or backend integration.
