# Phase 2D.2C bootstrap and security

`apps/api/src/integration/bootstrap-manifest.ts` is an explicit review artifact for a fictional organization, unit, author, reviewer and publisher. Issuer/subject values are placeholders. Grants are minimal placeholders and no administrator role exists. `fictionalBootstrapStatus.executable` is permanently false in this phase; there is no seed function, public bootstrap route or startup seeding.

Before executable bootstrap, approve the identity issuer and subject mapping, organization/unit ownership, exact role permissions, reviewer independence, publisher duties, retention and the operator trust ceremony. Do not substitute browser role selectors, employee names, email auto-linking or production identity claims. The manifest is not Welspun policy and does not establish SME qualification.

Session models store hashes of opaque values, explicit expiry, revocation and CSRF binding fields. The session interface requires an explicit active-record check for both idle and absolute expiry and revocation via `isSessionUsable`; TTL is only eventual cleanup. Login transactions are one-time records with expiry and consumption fields checked via `isLoginTransactionConsumable`. Security outcomes are immutable, bounded records separate from allowed transactional domain audit; their retention and failure-alert policy remain approvals.

Existing audit and receipt writes remain atomic with domain mutations in the same organization-fenced transaction. No integration adapter changes their durability label or bypasses current authorization/revision/digest/replay rules. Authentication, cookies, CSRF, login callbacks and trusted transport are deferred to Phase 2D.2D.

## Explicit proposed role review

The manifest now includes exact typed permission lists, still non-executable. The author has an own-scope authoring/review-submit role and a separate fictional-unit create grant, because own scope cannot create a resource. Reviewer decide/read is scoped to the fictional unit. Publisher review-assignment/publish/history/catalog read is also unit-scoped, with no organization-wide admin or security.manage. Grant records name their fictional grantee and proposed role. These are review proposals, not installed roles or corporate duties; no approval count/policy is selected. The publisher coordinates assignment in this proposal; a supervisor may choose another explicitly permitted coordinator.

Supervisor approval of fictional author/reviewer/publisher accounts is recorded; exact identity issuer/subject mapping, bootstrap operator, scope/permission plan and demonstration policy remain unresolved. No records are seeded or session issuer provided by this phase. Identity-related files from separate pre-existing Phase 2D.2D.1 work in the shared working tree are not part of this implementation's scope or approval.

Security-outcome category/reason fields use fixed vocabularies rather than arbitrary diagnostic strings; no body, URI, token or feedback field exists. Explicit usability checks reject future-issued, expired and revoked session records and invalid idle/absolute ordering. Tests persist revocation and consumption before reading them back. Native transaction probes validate storage rollback/unique constraints only; the unchanged domain test suites remain the evidence for organization fencing, audit-target checks, current authorization and receipt replay. No existing test audit adapter is relabeled or enabled on the integration database.
